# 05 — Логика прошивки и поэтапный план (M0 → M1 → M2)

Архитектура без RTOS: один главный цикл (`main loop`) для записи на SD и прерывания для быстрого захвата данных с датчика **BMI160**.

---

## 1. Состояния прибора (Вариант А)

[Включение питания]
│
▼

BOOT (Самодиагностика: датчик BMI160 → SD-карта → питание)
│ (если ошибка → мигаем кодом ошибки из Error.md)
▼

IDLE (Ожидание: светодиод PB2 коротко мигает раз в 2.5 сек)
│ ◄── нажата кнопка PC13 (антидребезг 30 мс)
▼

RECORDING (Запись: светодиод PB2 ВЫКЛЮЧЕН)
│ ◄── нажата кнопка PC13 повторно
▼

STOPPED (Закрытие файла: дописываем остаток, f_sync, f_close → PB2 ГОРИТ ПОСТОЯННО)

## 2. Как устроен поток данных (Кольцевой буфер)

1. **Производитель (Прерывания EXTI `PB5` + DMA SPI1, высокий приоритет):**
   * Как только в FIFO датчика накопилось 56 байт (8 фреймов × 7 байт = каждые 5 мс), срабатывает `INT1` (Active HIGH).
   * Останавливаем/проверяем DMA (Quiesce), читаем 2 байта `FIFO_LENGTH (0x22..0x23)` → получаем `fifo_bytes`.
   * Запускаем пакетное чтение `N = min(fifo_bytes, 252)` байт из `FIFO_DATA (0x24)` по SPI1 DMA в приёмный буфер `spi_rx_buf` (в D1 SRAM).
   * В прерывании завершения DMA разбираем фреймы по заголовкам: для каждого фрейма `0x84` забираем 6 байт `{x, y, z}` и кладём в текущий слот кольцевого буфера `ring[16][4096]` в **D1 SRAM** (64 КБ = 6.8 секунды запаса при задержках SD-карты).
   * Когда набралось 680 сэмплов (4080 байт), заполняем 16-байтный заголовок блока, делаем `__DMB()` и сдвигаем `head = (head + 1) & 15`.
   * Если кольцо полностью забито (`((head + 1) & 15) == tail`), новый недописанный блок сбрасывается, а в следующий блок ставится флаг `OVERFLOW` (датчик не останавливается).
2. **Потребитель (Главный цикл `while(1)`):**
   * Проверяет, есть ли готовый блок (`head != tail`).
   * Считает `crc32_payload`, дописывает его в заголовок блока.
   * Вызывает `f_write(&fil, ring[tail], 4096, &bw)` (строго 1 блок = 4096 байт за раз) и ждёт готовности карты (`CMD13`).
   * Только после подтверждения записи сдвигает `tail = (tail + 1) & 15`.
   * Раз в ~10–25 секунд делает `f_sync(&fil)` для сброса метаданных FAT на карту.
   * Кормит сторожевой таймер `IWDG` (таймаут ~8 с) только при реальном прогрессе.
   * Страховочный опрос: раз в 10 мс проверяет `FIFO_LENGTH` датчика — если по какой-то причине потерялся фронт `INT1` и `fifo_bytes >= 56`, принудительно запускает вычитку.

## 3. Простой план разработки (3 шага)

1. **Этап M0 (Плата + Датчик BMI160, без SD):**
   * Настроить UART1 (`PA9/PA10`) для отладки на ПК через WeAct MiniDebugger.
   * Добавить секцию `.d1ram` + `ASSERT` в скрипт линковщика, поднять стек MSP до 4 КБ.
   * Реализовать процедуру пробуждения SPI (`0x7F` → Soft Reset `0xB6` → `0x7F`), проверить чтение `CHIP_ID == 0xD1` и перевод акселерометра в Normal Mode (`CMD = 0x11`, проверка `PMU_STATUS == 0x10`).
   * Запустить пакетное чтение `FIFO_DATA (0x24)` через SPI1 DMA по прерыванию `PB5` (или по таймеру 10 мс), проверить разбор фреймов `0x84` и покой по оси Z (~`+2048` LSB при ±16 g).
2. **Этап M1 (SD-карта + Скорость):**
   * Подключить FatFs R0.12c + SDIO 4-bit (с `GPIO_PULLUP` на D0–D2 и CMD).
   * Сделать тестовую запись 1000 блоков по 4096 байт, проверить отсутствие ошибок `DMA_LISR` и задержек `CMD13` > 400 мс.
   * Проверить, что при одновременной работе SPI1 DMA и SDIO DMA сэмплы с датчика не теряются и не дублируются.
3. **Этап M2 (Боевая прошивка + Python):**
   * Собрать всю логику состояний `BOOT → IDLE → RECORDING → STOPPED` с кнопкой `PC13`, кодами светодиода (`Error.md`) и проверкой питания `VREFINT`/`PVD`.
   * Записать тестовый файл 10–30 минут, выдернуть питание на ходу и убедиться, что Python-скрипт на ПК без ошибок читает все целые блоки и строит БПФ (пик частоты и амплитуду).
