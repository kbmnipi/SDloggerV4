# 01 — Железо, распиновка и сборка (PlatformIO)

Компактный справочник для вибрологгера на базе **BMI160**. Задача прибора: писать сырые 3-осевые данные ускорения (1600 Гц, ±16 g) на MicroSD карту в течение 1–2 часов для последующего БПФ (поиска частоты и амплитуды резонанса балки) на ПК.

---

## 1. Железо

* **Отладочная плата:** WeAct Studio STM32F405RGT6 Core Board (LQFP64, кварц HSE 8 МГц, часовой кварц LSE 32.768 кГц).
* **Акселерометр:** модуль **GY-BMI160** (Bosch BMI160), подключён проводами длиной 8–10 см к **SPI1**.
  * *Примечание по модулю:* на типовом модуле GY-BMI160 пин `SA0 (SDO)` часто подтянут к GND (адрес I2C `0x68`), в режиме 4-wire SPI он работает как выход **MISO**, а пин `CS` включает режим SPI по первому нарастающему фронту.
* **Карта памяти:** встроенный слот MicroSD на плате WeAct (шина **SDIO 4-bit**). Карта FAT32 с кластером 32 КБ.
* **Питание:** отладка от БП KORAD / USB; в поле — батарея **Fanso ER14505M/S** (Li-SOCl2, 3.6 В, 2.2 Ач) + параллельно ей танталовый полимерный конденсатор **T521X227M016ATE035** (220 мкФ, 16 В, low-ESR) для сглаживания импульсов тока SD-карты.
* **Отладчик:** WeAct MiniDebugger (SWD + встроенный USART).

## 3. Тактирование (84 МГц постоянно)

Динамическое переключение частоты запрещено (иначе сбивается тактирование SDIO).

* **HSE:** 8 МГц (обязательно передать `-DHSE_VALUE=8000000` в компилятор!).
* **PLL:** `PLLM = 8`, `PLLN = 336`, `PLLP = 4`, `PLLQ = 7`.
* **Шины:** `SYSCLK = 84 МГц`, `AHB = 84 МГц`, `APB1 = 42 МГц` (таймер `TIM2` = 84 МГц), `APB2 = 84 МГц` (`SPI1`), `PLL48CK = 48 МГц` (`SDIO`).
* **Flash:** `FLASH_LATENCY_2` (2 wait states), регулятор питания `PWR_REGULATOR_VOLTAGE_SCALE1`.
* **TIM2:** предделитель `PSC = 83` → счётчик 1 МГц (1 тик = 1 мкс) + прерывание/флаг каждые 10 мс для страховки опроса датчика.

## 4. Среда сборки (`platformio.ini`) и грабли HAL 1.28.3

* **Платформа:** `platform = ststm32@19.1.0` (подтягивает `framework-stm32cubef4` версии **1.28.3**), `board = genericSTM32F405RG`, `framework = stm32cube`.
* **Обязательные флаги:**
  * `build_unflags = -Os` — без этого PlatformIO молча заменяет `-O2` на `-Os`.
  * `board_build.f_cpu = 84000000L`.
  * В `[env:release]` и `[env:debug]` явно писать `build_flags = ${common.build_flags} -O2` (или `-Og -g3`), так как наследование через `extends` теряет `-DHSE_VALUE=8000000`.
  * Добавить `-Wl,-Map=${BUILD_DIR}/firmware.map` и `-fstack-usage` для контроля стека и памяти.
  * Для WeAct MiniDebugger в `upload_command` / `debug_server` использовать `-c "transport select swd"` (вместо `hla_swd`).
* **Нюансы HAL F4 1.28.3:**
  * Задержка Flash называется `FLASH_LATENCY_2` (а не `FLASH_LATENCY_2WS`).
  * В `RCC_OscInitTypeDef` нет поля `HSEPredivValue`.
  * Напряжение ядра выставляется макросом `__HAL_PWR_VOLTAGESCALING_CONFIG(PWR_REGULATOR_VOLTAGE_SCALE1)`.
  * Обязательно определить глобальный `void SysTick_Handler(void) { HAL_IncTick(); }`, иначе `HAL_Delay()` зависнет.
* **Библиотеки в репозитории:** скопировать исходники FatFs R0.12c (`ff.c`, `ffconf.h`, `diskio.c`) и `stm32f4xx_hal_conf.h` в папку `lib/` проекта, чтобы все таймауты и настройки были под контролем в git.

## 5. Правило памяти (критично для DMA!)

У STM32F405 две области ОЗУ:
1. **D1 SRAM (`0x20000000`, 128 КБ):** сюда имеют доступ и процессор, и **DMA2**.
2. **CCM (`0x10000000`, 64 КБ):** видит **только процессор**. Контроллер DMA2 туда доступа не имеет!

**Жёсткое правило:**
* Все буферы, которые передаются в DMA (`ring[16][4096]`, буферы SPI1 для вычитки FIFO `spi_rx_buf[256]`, структуры `FATFS` и `FIL`, буфер `diskio`), а также **главный стек (MSP, размер 4 КБ)** должны лежать строго в **D1 SRAM** (помечать атрибутом `__attribute__((section(".d1ram"), aligned(4)))` и проверять границы через `ASSERT` в скрипте линковщика `.ld`).
* В `CCM` можно класть только таблицу CRC32 (8 КБ) и обычные переменные состояния, не связанные с DMA.
* Динамическая память (`malloc`, `new`) в прошивке **запрещена**.
